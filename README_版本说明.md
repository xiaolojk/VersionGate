## 旧版本（VersionGate v1.x）到底做了什么？

旧版的原理非常简单：**只改协议号**。

基岩版服务端绑定一个协议号（本项目是 `2225`），客户端上报的协议号不一致就被挡在门外。旧版插件拦截登录握手包，把客户端上报的 4 字节协议号改写为服务器协议号，让版本校验通过——**相当于只把"门牌号"改了**。

### 它做到了
- ✅ 让 1.26.x 各小版本客户端能"连进来"、进服通报真实版本
- ✅ 精确协议号白名单，不误伤 1.21.x 等跨代版本

### 它做不到（关键局限）

**只改协议号 ≠ 真正兼容。** 协议号只是握手时的版本号字段，而游戏过程中传输的**数据包结构**由版本决定。旧版客户端按旧结构发包，新版服务器按新结构解析，两边对不上会导致：

- 玩家/实体显示异常、皮肤错乱
- 部分物品、方块、村民交易行为异常
- 某些功能（新特性、动画、音效）失效或报错

打个比方：旧版只改了信封上的**收件人邮编**，让信能寄到；但信里写的**内容格式**对方看不懂。能进门，但没法正常玩。

这正是之前那句质疑——"你就单改了个协议号吗？跨版本麻烦的问题就是版本之间的数据包不一样"——说中的要害。**旧版确实没解决数据包不兼容的问题。**

## 新版本（v2.0.0）做了什么？——一个插件，两件事全包

v2.0 是**完整版**，把旧版的功能原样包含进来，并补上了真正缺失的那块：**数据包翻译**。

### 功能 1：握手准入（旧版做的事，v2.0 内置）
- 拦截登录包，按 1.26.x 白名单改写协议号，让旧版客户端连进来
- 进服时全服通报真实版本
- 精确白名单，不误伤跨代版本

### 功能 2：游戏包翻译（旧版做不到，v2.0 新增）
- 基于 Endstone 官方 [`bedrock-protocol`](https://github.com/EndstoneMC/bedrock-protocol)，按协议版本 `decode`/`encode`
- 旧版 payload → 用旧协议解码成对象 → 逐字段复制到新版对象 → 用新协议编码 → 交给服务器（服务器看到的就是标准新版包）
- 双向翻译（收包 + 发包）
- 2193→2225 实测：231 个共有包中 **223 个（96.5%）字节级兼容，只 7~8 个需翻译**，单次约 13µs

### 三重保护，绝不搞崩服务器
1. **自适应明文检测**：payload 是密文/不支持则自动进被动模式——**协议号改写仍生效**，只跳过包翻译
2. **只翻译旧版玩家**：协议号 ≠ 服务器协议号才翻译，同版本玩家零开销
3. **失败放行**：任何异常都吞掉原样放行，绝不阻断连接

## 我应该怎么装？

**只需要一个文件**：下载 `endstone_protocolbridge-2.0.0-py3-none-any.whl`，丢进 `plugins/` 目录，重启服务器即可。它同时完成握手准入、版本通报和包翻译。

- ✅ **推荐**：直接装 v2.0，`enable_version_bypass`、`enable_join_announcement`、`enable_translation` 三个开关默认全开，装完即用。
- ⚠️ **不要同时装 v1.3**：v2.0 已包含 v1.3 的全部功能，两个一起装会重复改写、重复通报。若服务器上已有 v1.3，请先移除它再装 v2.0。
- **跨大版本（如 1.21 → 1.26）**：暂不支持。v2.0 针对 1.26.x 相邻档位设计；跨大版本字段差异过大，需逐版本翻译链。

> ⚠️ **v2.0 前提**：`bedrock-protocol` 需要 **Python ≥ 3.12**。若你的 Endstone 跑在 Python 3.11，请先升级解释器（详见 [`protocolbridge/DEPLOYMENT.md`](protocolbridge/DEPLOYMENT.md)）。即使环境不满足，协议号改写仍会生效，只是包翻译不启动，不会搞崩服务器。
